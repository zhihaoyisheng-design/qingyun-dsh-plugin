# 青云 QINGYUN

青云是面向 DSH Desktop 的私人阅读工作台：首页、我的书架、问 AI、个人知识库。

## 0.4.0：独立讨论空间与可靠性修复

- 四种阅读讨论模式分别保存 DSH 会话：速览、结构、质疑、思想对话；旧版单会话继续作为「思想对话」使用。
- 修复删除书籍确认表单无法传递复选项的问题。
- 修复 PDF 快捷操作重复上传附件的问题。
- 聊天发送改用 requestId，不再用 20 秒超时竞速提前报错、遗留后台请求。
- IndexedDB 连接复用，并处理数据库版本升级时关闭旧连接。
- JSON 备份 v2 支持将 PDF 原文件一并导出，并在恢复时写回 IndexedDB；旧版备份仍可导入。


## 0.4.1：PDF 本地文字提取与 OCR

- PDF 导入时保存原文件，并使用 PDF.js 逐页提取文字；扫描页使用 Tesseract.js 中文简体 + 英文 OCR。
- 解析过程显示页码与进度条，提取结果按页码写入本地正文；AI 可直接分析提取文本，不必每次上传整个 PDF。
- PDF.js 与 Tesseract.js 作为 npm 依赖声明在客户端模块外部列表中；Tesseract 语言数据首次 OCR 时由其默认资源源下载，并由浏览器缓存。首次 OCR 需要网络；PDF 文件和页面图像在本地处理，不上传 OCR 服务。

## 0.4.3：PDF worker 与 OCR 语言加载修正

- PDF.js 固定使用与 npm 依赖版本一致的 worker 脚本；Tesseract 以 `['chi_sim', 'eng']` 的多语言数组启动，避免把组合语言误当成单一语言标识。
- PDF 文件和页面图像仍在本机解析；PDF.js worker、Tesseract worker 与首次使用的中英文识别数据需从 jsDelivr 加载，浏览器缓存后可复用。首次 OCR 需要网络连接。

## 0.4.2：知识图谱交互

- 第四页新增真实知识图谱视图：每条已保存知识为节点，已确认关系为连线；支持点击节点查看详情、来源和返回原文。
- 可在图谱与关系列表之间切换；关系列表可定位起点/终点并删除关系。图谱只呈现真实记录和用户确认的关系，不生成虚构节点。

## 0.3.0：插件内对话可用

- 会话服务改为**每次调用实时解析**，插件先加载、服务后注册也不会拿不到。
- 新建/打开书会话时自动套用可用模型（优先账户通道的非推理模型），可用「问 AI」右上角的下拉手动指定。
- `ask_user_question` 等待回答时，直接在插件里渲染问题卡片（选项 + 自定义输入 + 提交），不再卡死。
- 运行状态显示「深度求索中 · X 分 X 秒」；发送中、排队中都有可见反馈，20 秒无响应会报超时。
- 数据改为 IndexedDB 存储（含旧 localStorage 迁移），PDF 原文件单独存一份。
- 新增「诊断」和「重建会话」两个排障入口。

## 0.2.0：接入真实 DSH Desktop（0.2.2-rc.1）

原版依赖 `desktopWorkbenches` 工作台容器，该接口在当前 DSH Desktop 中不存在，插件装上也不会出现任何界面。0.2.0 改为使用 DSH 公开的 UI 挂载点：

- 左栏底部新增「青云」面板图标（`sidebar.panellist`，id `qingyun`）；主区域新增 `main` 面板（key `qingyun`）。
- `dsh.client.inject` 改为真实存在的 `@deepseek-ai/dsh-client-ui-sidebar`、`@deepseek-ai/dsh-client-ui-conversation`；客户端只声明 `slots` 依赖。
- 「发送到 DSH」通过 `ctx.sessions.create()` 建会话、`using(...).binding.session.prompt(...)` 发送；对话读 `eventSource`（`user/message`、`assistant/message`、`assistant/live-chunk` 的 `text-delta`）在**插件面板内**渲染，不再调用 `uiWorkspace.openSession`，不会跳出插件。
- **PDF 自动转附件**：导入时把 PDF 原文件存进 IndexedDB，发送时用 `ctx.fileUpload.upload(sessionId, blob)` 取回执，作为 `{type:'file', receiptId}` 随消息发出。
- **数据层换成 IndexedDB**：书籍、正文、记录不再塞 localStorage（约 5 MB 上限）；首次启动会把旧的 `qingyun:v43:data` 迁移过去。
- **聊天增强**：Markdown 渲染（标题/列表/引用/代码/粗体）、流式输出、停止生成、加载更早消息、错误重试、「存为知识」把某条回复直接存进知识库。
- **选段提问**：阅读器选中一段文字即出现「就这段问 AI」。
- **删掉冗余入口**：独立「AI 阅读总结」页并入问 AI 的四个动作——速览 / 结构 / 质疑 / 对话；移除复制模板、讨论模式按钮、最近交流列表、首页快速了解卡片；知识图谱降级为「记录之间的关系」列表；隐藏「思想变化」区块。
- 所有输入/确认改为插件自带对话框（Electron 不支持 `window.prompt`）。
- 书籍只有一个入口：导入文件（TXT / MD / EPUB 1 MB 以内；PDF 不限大小，作为附件交给 DSH）。
- 删除书籍：书架卡片、首页「继续阅读」、阅读器页都有入口，可选是否一并删除该书关联记录与关系。


## 0.1.0-alpha.27

- **首页与书架**：真实本地统计、继续阅读、最近沉淀、跨书联系，以及“5 分钟快速了解”入口；添加书籍、阅读进度、TXT/MD/EPUB 正文导入；PDF 仅登记来源信息，正文阅读与分析交由 DSH 原生会话中的 AI 处理（用户在 DSH 原生输入框添加 PDF 附件）；支持 TXT/MD 正文分章阅读、章节目录、关键词检索与定位；记忆每本书上次阅读章节，并可将当前章节保存为书签、选中正文保存为带书名和章节来源的原文摘录，统一进入个人知识库；知识库可按书籍、记录类型和知识分类筛选，书签、摘录和章节思考可返回对应原文章节；阅读器可直接记录关联当前章节的个人思考；EPUB 可按阅读顺序提取章节正文；PDF 不由青云解析；书架登记来源后，用户在对应 DSH 原生会话添加 PDF 附件，由 DSH AI 阅读与分析。
- **AI 阅读总结**：5 分钟快速了解、15 分钟理解全书、深入重点三档分析；点击“发送到 DSH 生成总结”后，青云将全文分块交给本书专属 DSH 会话，由 DSH AI 生成回复（结果显示在原生会话中，尚未实现青云内独立总结报告卡片）。
- **思想伙伴**：理解、讨论、挑战三种交流模式；讨论提示中的正文内容使用真实换行，便于在 DSH 原生会话中阅读；每本书独立关联一条 DSH 原生会话：首次创建并绑定，再次打开恢复原会话；思想伙伴页展示最近打开的书籍会话并支持恢复；用户明确触发后，将当前已导入的完整正文交给 DSH 原生会话；不再由青云设置 48,000 / 18,000 字符截断上限。DSH 或模型上下文容量不足时，必须如实提示，不能宣称完整处理。
- **个人知识库**：书本知识、我的观点、思想变化分类；真实记录自动成为图谱节点；用户可手动建立并二次确认关系，关系可删除；点击节点查看详情并返回原文；思想变化按时间呈现；可请求 DSH AI 分析候选联系或从书籍原文提炼候选观点，再由用户核对并手动确认保存；首页展示已确认的跨书联系。
- **数据备份**：导出 / 导入 JSON 备份；导入会替换当前本地数据，操作前会二次确认。
- **真实数据原则**：没有真实数据时显示空状态，不使用演示书籍、假统计、虚构 AI 回复或虚构知识图谱。

## 尚未完成

- PDF 由 DSH AI 处理，不在青云内解析；当前需用户在对应 DSH 原生会话中再次选择并添加 PDF 附件，青云尚未接入可验证的程序化附件上传接口。
- 书籍正文仍保存在青云本地数据中；用户点击“发送本书资料到 DSH”后，青云通过 DSH 原生会话 prompt 接口发送当前书籍资料，当前将完整正文切成 12,000 字符文本块，作为同一条原生 session.prompt 请求的多个 content block 发送；分块没有总量上限。大文件附件上传、跨请求分段索引仍待实现。单次请求或模型上下文可能存在宿主容量限制。AI 自动观点抽取及 DSH 回复自动解析入库仍待实现；AI 关系建议通过原生 DSH 会话发起，用户需查看建议后在知识库手动确认关系。
- 真实安装和运行验收尚未在用户的 Windows DSH Desktop 0.2.x 环境完成。

## 安装与开发

仓库：https://github.com/zhihaoyisheng-design/qingyun-dsh-plugin

DSH Desktop → 插件 → 添加插件，粘贴仓库地址。当前为早期 Alpha，尚未完成目标设备验收，不建议作为唯一知识数据存储。

客户端入口是 DSH Desktop 工作台规范要求的单文件模块加载入口；工作台注册使用 `desktopWorkbenches.register()`，会话由 DSH 原生服务管理。

## 数据与隐私

书籍元数据、TXT/MD 正文和手动记录保存在当前 DSH 客户端浏览器本地存储。导出备份包含导入正文和个人记录；请妥善保管。卸载插件不会主动清除本地数据。
